# Agent 开发工程师面试指南：深度求索 & 月之暗面

> 整理时间：2026 年 5 月  
> 覆盖范围：面试轮次与流程、考察方向、涉及知识面及深度、备考建议

---

## 一、深度求索（DeepSeek）

### 1. 面试轮次与流程

| 轮次 | 形式 | 时长 | 说明 |
|------|------|------|------|
| **笔试/Coding 测试** | 在线编程 | 1-2h | 面试前置环节，题目根据候选人背景**AI 定制生成**，非标准题库 |
| **技术一面** | 视频/现场 | ~1.5h | 由资深算法专家主持，侧重**机器学习基础知识深挖** |
| **技术二面** | 视频/现场 | ~1.5h | 另一位面试官，侧重**项目经验深度拷问**（思考方式、创新点、工程决策） |
| **HR/管理层面** | 视频/现场 | 30-60min | HR 主持或核心团队成员/创始人交流，考察文化匹配与潜力 |

> **特点**：高强度压力面试，单场面试可能长达 3 小时连续进行；面试官多为年轻的资深算法专家；公司扁平化管理，面试氛围高压但专业。

---

### 2. 考察方向总览

```
├── Agent 核心技术与理论（必考）
├── 工程化落地能力（重点加分项）
├── DeepSeek 技术栈深度理解（高频考点）
├── 行业应用与实战洞察
└── 思维潜力与抗压能力
```

---

### 3. 涉及知识面及深度

#### 3.1 Agent 核心技术与理论 ⭐⭐⭐⭐⭐

| 知识点 | 考察深度 | 典型问题 |
|--------|---------|---------|
| **Agent 架构（Planning / Memory / Tools）** | 需要理解本质，不能只背概念 | "描述 Agent 的核心模块及其协作方式" |
| **ReAct 框架** | 代码级实现 | "手写 ReAct 的消息格式设计，tool_response 传回机制" |
| **上下文管理** | 方案设计级 | "如何解决 ReAct 在长任务中的上下文爆炸问题？" |
| **记忆机制** | 架构设计级 | "短期会话记忆与长期业务记忆的存储方案对比" |
| **ReAct vs Plan-and-Execute** | 对比分析 | "在什么场景下选择哪种范式？为什么？" |

#### 3.2 工程化落地能力 ⭐⭐⭐⭐⭐

| 知识点 | 考察深度 | 典型问题 |
|--------|---------|---------|
| **系统稳定性 SLI/SLO** | 实战经验 | "如何定义 Agent 的 SLI/SLO？失败率和时延冲突时如何决策？" |
| **Tool Registry 设计** | 架构设计级 | "如何设计统一的工具注册中心？高风险工具的安全门禁策略？" |
| **成本优化** | 全链路思维 | "如何按租户/场景/模型维度统计 Token 消耗？" |
| **模型路由** | 策略设计 | "简单分类 vs 复杂推理场景下如何选择 DeepSeek-R1 或轻量模型？" |
| **上下文管理** | 方案设计 | "动态摘要、滑动窗口、常量工作空间等方案的优劣？" |

#### 3.3 DeepSeek 技术栈理解 ⭐⭐⭐⭐

| 知识点 | 考察深度 | 典型问题 |
|--------|---------|---------|
| **MoE 架构** | 原理 + 创新点 | "DeepSeek 的 MoE 相比传统 MoE 有哪些创新？专家分组与负载均衡？" |
| **长上下文 / 代码生成 / 数学推理** | 特性理解 | "DeepSeek 在这些方面的技术优势来源？" |
| **Thinking + Tool Calling** | 融合设计 | "如何将思考过程融入工具调用链？" |
| **强化学习合成数据** | 方法论 | "对于'难解答、易验证'任务，如何用 RL 合成高质量训练数据？" |

#### 3.4 行业应用与实战 ⭐⭐⭐

| 知识点                   | 考察深度        | 典型问题                                        |
| --------------------- | ----------- | ------------------------------------------- |
| **Coding Agent**      | 产品理解 + 技术实现 | "对 Claude Code / Cursor / Manus 的使用体验与技术分析" |
| **安全性与对齐**            | 策略设计        | "提示注入防护、PII 脱敏、权限最小化如何实现？"                  |
| **氛围编程（Vibe Coding）** | 认知          | "你如何看待 AI 辅助编程的发展趋势？"                       |

---

### 4. 备考建议

1. **项目深挖**：准备一个完整的 Agent 项目，能够清晰阐述架构设计、难点攻克、指标提升（用数据说话）
2. **代码能力**：扎实的 Python 编码能力，熟悉 LangChain/LangGraph **底层源码**
3. **阅读技术报告**：精读 DeepSeek-V3、R1 等技术报告，理解核心技术创新点
4. **心态建设**：面试可能遇到极高难度问题，保持冷静展示思考过程比得出正确答案更重要

## 二、月之暗面（Moonshot AI / Kimi）

### 1. 面试轮次与流程

| 轮次 | 形式 | 说明 |
|------|------|------|
| **技术一面** | 视频/现场 | 算法与编程考核 + Agent 基础知识，可能含**手写代码**环节 |
| **技术二面** | 视频/现场 | 深度技术交流，系统设计题，**项目经验深挖** |
| **技术三面（视岗位）** | 视频/现场 | 核心团队成员或技术负责人面试，开放性问题 + 技术品味考察 |
| **HR 面 / 综合素质面** | 视频/现场 | 文化匹配、稳定性、团队协作、薪资预期 |

> **特点**：节奏快，不设繁琐行政流程；面试官多为技术大牛或核心成员；极度重视 "AI Native" 工程实践能力；资深岗位轮次可能更聚焦于核心技术交流。

---

### 2. 考察方向总览

```
├── Agent 核心框架与原理
├── 工程落地能力（重中之重）
├── 大模型技术基础
├── "AI Native" 工程实践
├── 技术品味与极客精神
└── 文化契合度（"同路人"意识）
```

---

### 3. 涉及知识面及深度

#### 3.1 Agent 核心框架与原理 ⭐⭐⭐⭐⭐

| 知识点 | 考察深度 | 典型问题 |
|--------|---------|---------|
| **架构设计（ReAct / Plan-and-Execute / Agent Swarm）** | 方案设计级 | "设计一个能长期交互、自我反思的 Agent" |
| **记忆系统** | 深度方案 | "历史记录远超上下文窗口时，如何保证关键信息不丢失？" |
| **工具调用 Function Calling** | 实现逻辑级 | "如何处理工具调用的不稳定性、多步推理及错误重试？" |
| **Function Call vs MCP** | 对比分析 | "两者的差异及适用场景？" |
| **Agent Swarm 协作** | 认知理解 | "你对 Agent Swarm 协作模式的理解？" |

#### 3.2 工程落地能力 ⭐⭐⭐⭐⭐（最核心考察项）

| 知识点 | 考察深度 | 典型问题 |
|--------|---------|---------|
| **性能优化** | 实战级 | "如何优化推理速度和并发处理？" |
| **系统稳定性与鲁棒性** | 架构级 | "大规模并发下如何保证 Agent 的稳定性？" |
| **并发调度** | **手写代码** | "手撕一个可配置并发数的请求队列调度系统" |
| **异常处理与自愈** | 设计级 | "模型在复杂多步任务中报错/死循环，如何设计监控与自愈机制？" |
| **底层集成** | 深度工程 | "是否具备 C++/JNI 等深入系统底层解决性能问题的能力？" |

#### 3.3 大模型技术基础 ⭐⭐⭐⭐

| 知识点 | 考察深度 | 典型问题 |
|--------|---------|---------|
| **Transformer 架构** | 原理级 | "Attention 机制、位置编码、解码策略的底层原理" |
| **手写算子** | **代码实现** | "手写 MHA（多头注意力）、TopK 算子、KV Cache 压缩" |
| **训练与微调** | 方法论 | "SFT / RLHF / DPO 的原理与工程实现" |
| **推理加速** | 实战 | "vLLM、PagedAttention 等推理优化技术" |
| **CUDA 优化** | 硬核工程 | "分布式训练细节、CUDA kernel 优化" |

#### 3.4 "AI Native" 工程实践 ⭐⭐⭐⭐

| 知识点 | 考察深度 | 典型问题 |
|--------|---------|---------|
| **AI 辅助编程** | 深度使用 | "如何利用 Cursor/Copilot 进行代码重构和快速交付？" |
| **AI Native 开发模式** | 理念认知 | "在 AI 时代，工程师的核心竞争力是什么？" |
| **技术品味（Taste）** | 开放讨论 | "在 AI 开发中，你认为最重要的'品味'是什么？" |

### 5. 备考建议

1. **摒弃死记硬背**：月之暗面寻找的是 "Product Builder"，能把 AI 能力变成产品的工程师
2. **深入理解 Kimi 产品**：熟悉 Kimi Code / Agent Swarm / Kimi Claw 等功能，思考底层技术架构
3. **准备从 0 到 1 项目**：开源贡献、独立作品、高质量技术博客是极大加分项
4. **展示 AI 工具应用**：体现你对 AI-Native 开发模式的深度理解
5. **前沿论文追踪**：关注 NeurIPS / ICML 等顶会，以及 Kimi 相关技术论文

## 三、两家公司对比

| 维度 | 深度求索（DeepSeek） | 月之暗面（Moonshot AI） |
|------|---------------------|----------------------|
| **面试风格** | 高压力、深度拷问、连续长时间 | 高标准、务实高效、快节奏 |
| **面试轮次** | Coding 测试 + 2 轮技术 + HR/管理层 | 2-3 轮技术 + HR |
| **最看重** | 深度思考 + 底层原理 + 研究潜力 | 工程落地 + 技术品味 + AI Native |
| **Agent 考察侧重** | 理论深度 + 架构理解 + 成本优化 | 工程实现 + 系统稳定性 + 手写代码 |
| **模型知识要求** | 必须深入理解 DeepSeek 技术报告 | 需了解 Kimi 产品及前沿模型 |
| **编码考核** | AI 定制题目，非标准题库 | LeetCode 高难度 + 手写算子（MHA/TopK 等） |
| **文化关键词** | 扁平化、追求卓越、天才潜力 | AI Native、极客精神、同路人 |
| **加分项** | 对 DeepSeek MoE/R1 有深入研究 | 开源贡献 + 从 0 到 1 项目经验 |
