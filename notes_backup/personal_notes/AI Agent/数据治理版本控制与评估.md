# 数据治理、版本控制与评估 (Data Governance, Versioning & Evaluation)

本篇笔记重点梳理在 AI 系统的研发生命周期中，如何实施标准化的数据存储审计、Prompt 版本迭代追踪、回归测试以及黄金评测集构建。

---

## 1. 结构化审计日志 (Structured Audit Log)

### 概念详解
在系统运行时，仅输出非结构化的文本日志（如 Print 输出）极难被自动化系统分析和可视化。
**结构化审计日志** 要求将系统每一次核心调用（如 API 请求、大模型调用）的关键元数据（包括请求 ID、耗时、状态码、输入输出参数、组件版本）以统一的格式（如 JSON 或单行 JSONL）记录下来。

### 知识点关联
* **与 Web 服务的关联**：这与 Nginx 的访问日志（Access Log）或者 Docker 容器收集的结构化 JSON 日志（JSON-file Logging）是一类概念，核心目的都是为了让日志能直接被数据分析工具（如 ElasticSearch、Pandas）进行流式处理。

### 工业级应用举例
在大模型推理服务中，每次推理完成后，系统会将一行包含 `{"task_id": "xxx", "latency_ms": 150, "prompt_version": "v1.2", "status": "success"}` 的日志追加到运行日志文件中。数据工程师可以实时收集这些 JSONL 文件，直接用 pandas 进行并发统计，精准画出时延和准确率的分布图。

## 2. 语义版本控制 (Semantic Versioning for Prompt)

### 概念详解
随着大模型能力的迭代，Prompt 会频繁进行增删改动。如果不加以管理，一旦线上出现表现下滑（Bad Case），将无法定位到底是哪次 Prompt 修改引入了 bug。
**Prompt 语义版本控制** 是指将 Prompt 作为代码资源进行管理，为其分配符合语义的版本号（如 `v1.0`，`v1.1`），并在模型调用时将对应的版本标签打在结构化日志中。

### 知识点关联
* **与软件版本管理的关联**：它和软件工程中的语义化版本号管理规范（SemVer，如 `Major.Minor.Patch` 结构）以及 Git 的标签管理（Git Tags）属于完全一致的管理思想。

### 工业级应用举例
在大模型应用开发中，开发者在配置文件中集中管理 Prompt。当修改了 Prompt 模板中的某些修饰词时，会将版本号升级为 `v1.1` 并做好记录。线上日志收集到该标签后，我们就可以在离线评测中将 `v1.1` 的准确率与 `v1.0` 进行 A/B 对比，做到科学灰度发布。

## 3. 回归测试 (Regression Testing)

### 概念详解
在软件开发中，当我们为了优化或修复某一个特定问题而修改代码时，可能会无意中破坏原本运行良好的其他功能（俗称"按下葫芦起了瓢"）。
**回归测试** 是指在系统发生任何代码或资源更新后，重新运行一整套已有的测试用例，来验证新的修改没有引起老功能指标下滑的测试行为。

### 知识点关联
* **与自动化测试的关联**：这与你在传统后端开发中使用 `pytest` 运行单元测试，或是在 PyTorch 代码重构后重新跑一遍历史验证集指标是同一种研发保障手段。

### 工业级应用举例
在 AI 产品的 CI/CD（持续集成）流程中，每次开发者提交新的 Prompt 或是更换微调模型权重时，流水线会自动调用评测脚本，将黄金评估集中的所有输入在当前新系统上运行一遍。只有在准确率指标没有发生退化（Regression）的前提下，才允许代码合并与自动部署。

## 4. 黄金评估集 (Golden Eval Set)

### 概念详解
大模型测试中如果使用随机抽样的数据，可能会包含大量简单重复样本或脏数据，导致评测指标无法反映系统的真实可用度。
**黄金评估集** 是一套经过人工专家精心设计、层层筛选过滤出来的、覆盖了系统所有高频核心场景与极端边界场景（Edge Cases）的权威评测数据集。它是系统上线前必须跨越的硬性门槛。

### 知识点关联
* **与机器学习基础的关联**：它相当于机器学习竞赛（如 Kaggle）中的 Private Test Set（私有测试集）或高考真题卷，代表了最能检验出真实实力、最为严格的评测标准。

### 工业级应用举例
在企业级 Agent 的研发流水线中，通常会维护一个包含数百到数千条用例的 Golden Eval Set。每一条用例都包含精确的"场景描述"、"输入文本"、"期待执行的 API"和"校验规则"。它是评估系统每一次架构升级、大模型微调成败的决定性评判标准。

## 附录：图像采集与零样本视觉概念 (OpenCV & Zero-shot VLM)

### A. OpenCV (开源计算机视觉与图像流采集)
* **概念详解**：计算机视觉的开源事实标准库。在多模态 Agent 系统中，主要负责从物理摄像头实时拉取图像帧（Video Frames）、进行通道转换（如 BGR 转 RGB）、裁剪掉无关背景，并将图片压缩转化为 base64 文本数据以便网络传输。
* **与 PyTorch 关联**：读取的图片表现为 NumPy 多维数组，转换为 RGB 格式后经过 `torchvision.transforms.ToTensor()` 即可转为 PyTorch 接收的张量（Tensor）。

### B. Zero-shot VLM 推理 (零样本视觉语言大模型推理)
* **概念详解**：利用在海量图文对上训练好的多模态大模型，直接输入图像和一段自然语言问题，让模型在**完全没有针对该特定故障或物体做过微调**的情况下（Zero-shot），依靠通用的视觉常识直接进行内容理解和推理输出。
* **与 Transformer 注意力机制关联**：VLM 使用 ViT 提取图像特征，然后通过交叉注意力（Cross-Attention）将文本和图像序列进行特征对齐和融合解码。
