# 增量更新策略

## 问题

初期 18 个文件全量重建无所谓，但知识库每 1-2 周更新一次，文件逐渐增多后，每次全量重建不可接受。需要支持：**新文件追加、旧文件更新、已删文件移除**。

## 核心思路

用**文件路径 + 修改时间**做去重和变更判断，避免重复索引已入库的文件。

## 方案

### 阶段一：全量建库（当前版本）

函数签名预留增量更新的口子：

```python
def build_index(docs_dir: str, persist_dir: str):
    """全量重建向量索引。"""
    pass

def update_index(docs_dir: str, persist_dir: str, index_record: str):
    """增量更新向量索引。"""
    pass
```

先实现 `build_index`，`update_index` 留到后续迭代。

### 阶段二：增量更新（后续实现）

#### 索引记录文件

用一个 JSON 文件（如 `indexed_files.json`）记录已入库文件的路径和修改时间：

```json
{
  "AI Agent/AI Agent架构与并发控制流.md": "2026-06-01T10:30:00",
  "LLM微调/大模型微调与参数高效化.md": "2026-06-01T10:30:00"
}
```

#### 增量逻辑

```python
def update_index(docs_dir, persist_dir, index_record):
    # 1. 读取已入库记录
    indexed = load_index_record(index_record)

    # 2. 扫描当前全部 .md 文件
    current_files = scan_md_files(docs_dir)

    # 3. 找出三类文件
    new_files = []       # 不在 indexed 中的
    modified_files = []  # 在 indexed 中但 mtime 变了
    deleted_files = []   # 在 indexed 中但文件已不存在

    # 4. 处理
    # 新增/修改 → 加载→切块→add_documents()
    # 删除 → collection.delete(where={"source": file_path})
    # （ChromaDB 的 delete 按 metadata 过滤，需要 source 字段）

    # 5. 更新 index_record
    save_index_record(index_record, current_files)
```

### metadata 约定

加载文档时，metadata 中必须包含：

```python
doc.metadata["source"] = file_path   # 文件相对路径，用于去重和删除
doc.metadata["mtime"] = os.path.getmtime(file_path)  # 修改时间，用于变更判断
```

## 注意事项

- 切块参数（chunk_size、overlap）变更后需要全量重建
- 嵌入模型换了也需要全量重建
- ChromaDB 的 `delete` 按 metadata 过滤删除，如果 metadata 信息不够就会删不干净
