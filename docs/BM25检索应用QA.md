# BM25 检索应用 QA

## Q1：BM25 是什么？和向量检索有什么区别？

**A：** BM25 是稀疏检索（关键词匹配），向量检索是稠密检索（语义匹配）。

| 维度 | 稠密检索（向量） | 稀疏检索（BM25） |
|---|---|---|
| 匹配方式 | 语义相似度（"热"→"空调"） | 精确关键词（"热"→匹配"热"） |
| 优点 | 理解同义词、近义表达 | 精确命中，不依赖 embedding 质量 |
| 缺点 | 可能漏掉精确关键词 | 同义词匹配不到 |
| 场景 | 开放式问答 | 产品名、型号、术语精确查找 |

两者互补，生产环境通常混合使用（Hybrid Retrieval）。

## Q2：BM25 索引基于什么单位检索？

**A：** 和向量检索在同一个单位上工作——就是切好的 `final_chunks`（标题切块+兜底切分后的语义块）。区别在于：

- 向量检索：把 chunk 转为 768 维向量，算余弦相似度
- BM25：把 chunk 分词，统计词频，算 TF-IDF 变体得分

## Q3：BM25 索引需要持久化吗？

**A：** 推荐用 **pickle** 持久化整个 BM25 索引对象。理由：

| 方案 | 评价 |
|---|---|
| pickle | ✅ 直接序列化 Python 对象，加载即用，秒起 |
| JSON | ❌ BM25 内部是 Term-Document 矩阵，JSON 无法表达对象引用 |
| SQLite | ❌ 为一个索引开一个数据库，过度设计 |
| 每次重建 | ❌ 简单粗暴，但笔记多了以后重复计算 |

```python
import pickle

# 保存
with open("bm25_index.pkl", "wb") as f:
    pickle.dump(bm25, f)

# 加载
with open("bm25_index.pkl", "rb") as f:
    bm25 = pickle.load(f)
```

## Q4：BM25 需要独立于向量库的一套增量更新吗？

**A：** 不需要独立写一套增量逻辑。可以用同一个 `indexed_files.json` 做变更检测——检测到笔记有变动时，**全量重建 BM25 索引**即可。因为 BM25 重建只有分词+词频统计，没有模型推理，非常快（几百个 chunk 毫秒级），没必要为它写增量。

## Q5：pickle 文件怎么保证和数据一致？

**A：** 不需要反向对比 pickle。BM25 是 `final_chunks` 的派生数据，不用独立验证一致性。启动时判断：如果 pickle 文件不存在，或者 `indexed_files.json` 有更新，就重建。重建全程不到一秒。

## Q6：BM25 和向量检索怎么组合使用？

**A：** 两种思路：

1. **各自独立检索，结果合并去重**：BM25 取 top-k，向量检索取 top-k，合并后按分数排序
2. **先 BM25 粗筛，再向量精排**：先召回 100 条，再对 100 条做向量排序取 top-5

小规模知识库（当前 少量 笔记）用方式 1 即可，实现简单、效果差异不大。
