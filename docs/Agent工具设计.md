# Agent 工具设计

## 场景分析

笔记助手 Agent 需要三种能力：查笔记、写笔记、管目录。对应三个 `@tool` 函数。

## 工具清单

### 工具 1：`search_notes` — 语义检索笔记

| 项 | 说明 |
|---|---|
| **触发场景** | 用户问"RAG 怎么做的""Transformer 注意力机制是什么""有没有关于部署的笔记" |
| **输入** | `query: str` — 用户的自然语言查询 |
| **输入** | `k: int = 5` — 返回 top-k 个最相关片段 |
| **输出** | `str` — 拼接好的检索结果文本，包含 chunk 内容和来源文件 |
| **内部逻辑** | 调用 `rag.retrieve(vectorstore, query, k)`，把返回的 Document 列表格式化为可读文本 |

**为什么返回 str 而不是 List[Document]：** Agent 的 LLM 需要文本上下文做推理。格式化后的字符串直接作为工具结果注入对话。

### 工具 2：`create_note` — 新建笔记文件

| 项 | 说明 |
|---|---|
| **触发场景** | 用户说"帮我记一下""写一篇笔记""新建一个文档" |
| **输入** | `title: str` — 笔记标题（会作为文件名 `{title}.md`） |
| **输入** | `content: str` — 笔记正文（Markdown 格式） |
| **输入** | `folder: str = ""` — 可选，存到哪个子目录 |
| **输出** | `str` — 成功/失败信息，含文件路径 |
| **内部逻辑** | 拼接路径 → 检查同名文件 → `open().write()` |

**注意：** `title` 中不应包含路径分隔符和非法字符，需要做简单清洗。

### 工具 3：`create_folder` — 新建文件夹

| 项 | 说明 |
|---|---|
| **触发场景** | 用户说"建一个 XXX 的文件夹""整理一下目录" |
| **输入** | `folder_name: str` — 文件夹名（相对于笔记根目录） |
| **输出** | `str` — 成功/失败信息 |
| **内部逻辑** | `os.makedirs()` → 返回结果 |

## 工具边界决策

### 不要做的

| 不做的功能 | 原因 |
|---|---|
| 删除笔记 | v1 不引入破坏性操作，Agent 误判代价太高 |
| 修改已有笔记 | 需要先检索再定位再编辑，链路过长，留到 v2 |
| 全量列出文件 | 笔记 18 篇，全列出来浪费 token；检索已经有针对性 |

### 后续可加

- `update_note`：检索定位 + 追加/替换内容
- `list_notes`：列出某个目录下的所有笔记
- `delete_note`：确认后删除（需二次确认机制）

## tools.py 结构示意

```python
from langchain.tools import tool

@tool
def search_notes(query: str, k: int = 5) -> str:
    """语义搜索个人笔记，返回最相关的片段及其来源文件。
    当用户询问知识相关问题时使用此工具。"""
    ...

@tool
def create_note(title: str, content: str, folder: str = "") -> str:
    """在笔记目录下创建新的 Markdown 笔记文件。
    当用户要求记录、新建笔记或保存内容时使用此工具。"""
    ...

@tool
def create_folder(folder_name: str) -> str:
    """在笔记目录下创建新的子文件夹。
    当用户要求新建目录、整理分类时使用此工具。"""
    ...
```

## 返回值设计原则

1. **返回 str**：Agent 的 LLM 需要文本上下文，str 是最直接的格式
2. **含路径信息**：成功时返回文件路径，Agent 能告诉用户"已保存到 XXX"
3. **含错误信息**：失败时返回具体原因，Agent 能向用户解释或换策略
